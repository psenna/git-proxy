{{- if not .Values.config.auth.existingSecret }}

================================================================================
WARNING: OPEN RELAY -- no config.auth.existingSecret configured
================================================================================
git-proxy itself logs this at startup:

  "git-proxy: WARNING: no auth.tokens configured -- the HTTP frontend is an
  OPEN relay (any client can reach the upstream with the proxy's upstream
  credentials). Configure auth.tokens in production."

Any client that can reach this Service can use it as an unauthenticated proxy
to the configured upstream. Create a Secret holding an `auth:` fragment and
set config.auth.existingSecret before running this anywhere but a throwaway
dev/test environment. See the chart README's "Secrets & the fragment-assembly
mechanism" section.
{{- end }}

{{- if and .Values.config.ssh.enabled .Values.config.ssh.hostKey.allowEphemeral }}

================================================================================
WARNING: ephemeral SSH host key
================================================================================
config.ssh.hostKey.allowEphemeral=true means a NEW SSH host key is generated
every time the pod restarts. Every client will see a host-key-changed
warning (or an outright rejection, depending on their known_hosts policy)
after each restart. This is fine for dev/test; for anything longer-lived,
create a stable host-key Secret instead (see the chart README's "SSH host
key" section) and set config.ssh.hostKey.existingSecret.
{{- end }}

{{- if and .Values.config.audit.enabled (not .Values.persistence.audit.enabled) }}

================================================================================
WARNING: audit log has no persistent storage
================================================================================
config.audit.enabled=true but persistence.audit.enabled=false, so the audit
log lives on an emptyDir and is LOST on every pod restart (rescheduling,
node drain, rollout, OOM-kill, ...). If the audit trail matters for
compliance, set persistence.audit.enabled=true and provide a PVC. See the
chart README's "Persistence" section.
{{- end }}

{{- if .Values.unsafeAllowMultipleReplicas }}

================================================================================
WARNING: multiple replicas (unsafeAllowMultipleReplicas=true)
================================================================================
git-proxy keeps per-pod local state (the inspection-mirror cache and the
append-only audit file) with a single-writer assumption. With
replicaCount > 1 each pod maintains an INDEPENDENT mirror cache (wasted disk,
slower cold starts) and writes its OWN audit file, so the compliance-relevant
audit trail is SPLIT across pods with no aggregation. See the chart README's
"Multi-replica" section before relying on this in production.
{{- end }}
